# Contributing

Dar Tech OS is developed through controlled sprint/ticket execution.

## Rules
- One coherent ticket/slice at a time.
- Preserve business rules in the documentation.
- Add tests with implementation changes.
- Run quality gates before submitting a PR.
- Use ADRs for material architecture decisions.
- Do not bundle unrelated refactors with feature work.

## Commit examples
- `chore: initialize engineering foundation`
- `feat(identity): add session revocation foundation`
- `fix(finance): prevent duplicate payment allocation`
- `docs: record queue provider ADR`
